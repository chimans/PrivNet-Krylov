MODELED CKKS RESULTS - NOT HARDWARE MEASUREMENTS

Purpose
-------
These files provide representative CPU estimates for the case where a TenSEAL
runtime was not available during the build. They are calculated from published
CKKS microbenchmarks and explicit scaling assumptions; they are not measurements
from the hardware used to build this repository.

Calibration source
------------------
Benaissa, Retiat, Cebere, and Belfedhal (2021), "TenSEAL: A Library for Encrypted
Tensor Operations Using Homomorphic Encryption", arXiv:2104.03152 / ICLR 2021
DPML. Their CKKSVector benchmarks were run on an AWS EC2 c4.2xlarge system with
8 vCPUs, an Intel Xeon E5-2666 v3 at 2.9 GHz, 15 GiB RAM, Ubuntu Server 20.04,
Python 3.8, N=8192 and a 200-bit coefficient modulus. For shape [256], the
reported mean timings include add=0.08 ms, multiply=4.45 ms, add-plain=0.80 ms,
multiply-plain=1.75 ms, dot=20.15 ms, and quadratic polyval=10.55 ms.

Target context
--------------
N=16384; coeff_mod_bit_sizes=(60,40,40,40,40,40,40,40,60), total 400 bits;
global scale=2^40; slot capacity=8192. These parameters belong to the benchmark
model and are not, by themselves, a security proof.

Interpretation
--------------
The latency model rescales operations dominated by NTT and key switching using
N log2(N) and the number of RNS limbs, and derives a rotation anchor from the
published TenSEAL dot benchmark. The degree-5 polynomial is modeled as 2.2 times
the target-context quadratic polyval cost. This is an estimate, not a TenSEAL
measurement.

The suggested scenario ranges are ±25% for server time, ±35% for encryption,
and ±30% for working-set memory. The payload value is a raw-RNS representation
proxy and is not a TenSEAL serialization measurement. Evaluation-key memory is
not included.

For direct measurements, install requirements-ckks.txt and run:
  python code/real_ckks_public_benchmark.py --repeats 5

Keep the resulting measured files separate from these calibrated estimates.
