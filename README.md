# PrivNet-Krylov

This repository contains the code and experimental results for **PrivNet-Krylov: Client-Side Krylov Compilation for Topology-Private Homomorphic Spectral GNN Inference**.

The repository is intended to make the experiments easy to reproduce. It includes the main implementation, benchmark scripts, tests, figures, and the data products generated by the experiments.

## What is included

The current version contains four main parts of the experimental work:

1. A larger public-data experiment using a deterministic 10-nearest-neighbour graph built from scikit-learn's handwritten-digits data. The graph contains 1,797 nodes and 12,339 undirected edges. Across five stratified splits, the degree-5 polynomial model obtains 97.47% ± 0.37 percentage points test accuracy and 99.02% ± 0.52 percentage points agreement with the corresponding ReLU model.
2. Activation calibration using training and validation data only. Test nodes are kept out of the interval-selection step and are used for the final evaluation.
3. A privacy-matched recurrence baseline (`FS-ETHE`) implemented in `code/privacy_matched_baseline.py`. For the declared circuit, the baseline requires 2,312 graph ciphertext products on the Karate graph and 115,008 on the larger Digits graph. KGC has no graph-dependent ciphertext products after upload.
4. An optional TenSEAL CKKS runner. Actual CKKS results are written only when the TenSEAL implementation is really executed. The repository keeps these results separate from the calibrated estimates.

The regression suite contains 14 tests.

## Numerical results and how they were obtained

The repository uses several kinds of results, and they should not be mixed together:

- **Executed:** results produced directly by the supplied plaintext/polynomial experiments.
- **Simulated:** controlled numerical perturbation experiments used to study approximation robustness.
- **Analytical:** operation counts and packing calculations obtained from the circuit definition.
- **Calibrated estimate:** timing and memory estimates obtained from a model based on published CKKS benchmarks.
- **Measured real CKKS:** results produced by an actual TenSEAL run on the machine where the benchmark is executed.

In particular, the CKKS estimates included in the repository are not hardware measurements. If TenSEAL is not available, the benchmark script does not create a fake measurement.

## Reproducing the experiments

Create a virtual environment and install the standard dependencies:

```bash
python -m venv .venv
source .venv/bin/activate       # Windows: .venv\Scripts\activate
pip install -r requirements.txt
```

Then run the main experiments:

```bash
python code/privnet_krylov.py --seed 7 --out outputs
python code/run_multiseed.py --seeds 1 2 3 4 5 6 7 --out outputs/multiseed
python code/public_graph_benchmark.py --out outputs/public_graph
python code/larger_public_graph_benchmark.py --out outputs/larger_public_graph
python code/privacy_matched_baseline.py --out outputs/matched_baselines
python code/calibrated_ckks_estimator.py
python -m pytest -q
```

## Running the CKKS benchmark

The CKKS experiment is optional. Install the additional dependencies on the machine on which you want to collect timings:

```bash
pip install -r requirements-ckks.txt
```

For the Karate graph:

```bash
python code/real_ckks_public_benchmark.py \
  --artifact outputs/public_graph/karate_seed7_ckks_artifact.npz \
  --label "Zachary Karate Club" \
  --out outputs/real_ckks/measured \
  --repeats 5 --warmup 1
```

A successful run produces:

- `measured_ckks_results.json`
- `measured_ckks_results.csv`
- `measured_ckks_table.tex`

The recorded metadata include the CKKS parameters, CPU and RAM information, Python/NumPy/TenSEAL versions, warm-up and repetition counts, key and context setup, client compilation, encryption/server/decryption times, serialized ciphertext size, numerical error, accuracy, prediction agreement, and process-memory change when `psutil` is available.

The same runner can be used with the 1,797-node Digits artifact:

```bash
python code/real_ckks_public_benchmark.py \
  --artifact outputs/larger_public_graph/digits_knn_seed7_ckks_artifact.npz \
  --label "Digits 10-NN graph" \
  --out outputs/real_ckks/measured_digits \
  --repeats 3 --warmup 1
```

The sparse column-wise SK-HE recurrence is not optimized, so the larger graph can take a substantial amount of time to run.

## Baselines

`SK-HE` leaves the graph shift visible to the evaluator. It is therefore useful as a placement comparison, but it is not a topology-private competitor.

`FS-ETHE` is the privacy-matched reference. The graph-dependent diagonal values are encrypted and the server executes the same fixed loop, including padded zero diagonals. The baseline is mainly there to make the operation accounting transparent rather than to claim a state-of-the-art runtime.

## Repository layout

- `code/` — implementation, benchmark, baseline, and CKKS scripts.
- `tests/` — regression tests.
- `outputs/public_graph/` — Karate graph results and the seed-7 CKKS artifact.
- `outputs/larger_public_graph/` — Digits graph results and the seed-7 artifact.
- `outputs/matched_baselines/` — analytical comparison of FS-ETHE, SK-HE, and KGC.
- `outputs/real_ckks/` — calibrated CKKS files and the directory used for real measurements.
- `figures/` — figures generated for the project.

## Note about the CKKS estimates

The calibrated CKKS values in the repository are sensitivity estimates, not direct measurements. They should not be described as measured hardware timings. For publication-quality measurements, run `code/real_ckks_public_benchmark.py` with the optional TenSEAL environment and keep the generated environment metadata with the results.
